# 六镜片装配失败与回退复现（2026-10-06）

## 测试结果

在独立 `ROS_DOMAIN_ID=91` 中使用工作区 MuJoCo、MoveIt 和当前默认
`assembly_flow.yaml`，任务选择种子为 7，记录任务 DEBUG 日志和规划场景。
原有用户仿真进程未停止、未修改。六片全流程约 209 秒完成：

| 中心接口 | 镜片 | 机械臂 | 抓取接口 |
| --- | --- | --- | --- |
| S0 | 6 | A | S2 |
| S3 | 3 | B | S1 |
| S1 | 5 | A | S2 |
| S2 | 4 | B | S4 |
| S5 | 1 | A | S4 |
| S4 | 2 | B | S2 |

实际安装顺序为 `S0 → S3 → S1 → S2 → S5 → S4`。最终六个接口均对合，
最大位置误差约 **0.0062 mm**，最大姿态误差约 **0.0000181 rad**，
MoveIt 无残留附着对象，六片镜片均为已安装的世界碰撞对象。两臂回 home。
本轮没有 action 最终失败、控制器超时或控制器执行失败。

首次从空 MoveIt 场景启动时初始化失败一次，见下文；修复后才进行上述完整测试。
另外重跑了首对镜片 S0/S3，顺序变为 S3→S0，成功，未触发碰撞协调回退。
`seed=7` 控制任务选择，不固定 STOMP 的随机扰动；重放可重复失败机制，
不能保证随机优化轨迹逐点相同。

### 1. 初始化：删除不存在的对象

空场景中没有六个 `space_sim_carried_lens_N` 对象，重置却无条件发 REMOVE，
MoveIt 返回 `apply_planning_scene` 失败。之前的重复重置测试已有对象，未覆盖此情况。
已修复 `SceneManager::clearTaskObjects`：读取实际世界对象及附着对象，只删除存在项。
随后从同一空场景成功初始化并完成全流程。

### 2. 存储释放后的 2 cm 下降

| 对象 | 原运行 | 冻结状态重放 | 判定 |
| --- | --- | --- | --- |
| A/镜片6/S2 | 71.4% 前缀，实测下降 15.04 mm | 开/关碰撞均约 70%；完整目标纯 IK 为 -31 | 当前固定姿态与连续 IK 的可达性问题，非碰撞过滤 |
| A/镜片5/S2 | 14.3% 前缀，实测下降 2.19 mm | 开/关碰撞均约 15%；完整目标纯 IK 成功 | 连续直线分支接近关节限位，目标本身可达 |

镜片5下降前 `arm_A_ur_shoulder_lift_joint=6.2709188345 rad`，
最后可达直线点为 `6.2806743702 rad`，上限为 `2π≈6.2831853072 rad`。
完整目标的另一 IK 解将该关节绕回 `0.0628644160 rad`，其他关节也换支路。
因此“完整目标有 IK”不能保证当前分支能连续沿直线抵达。不能通过突然切换支路
绕过短直线阶段的要求。两次都没有 STOMP 回退，也没有执行旋转脱离。
重放比例略有不同是记录状态与分段数的差别，原因判定一致。

### 3. 移出阶段的七个失败终点

| 机械臂/镜片 | 失败姿态候选数 | 原参考完成率 |
| --- | ---: | --- |
| A/6 | 1 | 74.2% |
| A/5 | 1 | 91.7% |
| B/4 | 2 | 92.5%、38.8% |
| A/1 | 2 | 92.5%、38.8% |
| B/2 | 1 | 85.0% |

对每个候选重放相同目标 TCP 和七个 IK 种子，分别开启和关闭碰撞检查，
均返回 -31。增加纯 IK 求解时间至 1 秒仍失败。因此直接触发下一候选的原因是
**当前 KDL 无法求出指定位置与固定末端姿态的解**，并不是 STOMP 优化失败，
也不是 ACM 排除了不够多的对象。这不能作为“数学上不存在任何 IK 解”的证明。

镜面竖直是路径约束；终点候选仍指定完整 TCP 姿态。路径允许法向旋转，
不代表终点 IK 自动拥有该自由度。改候选姿态后，各镜片均用 STOMP 移出成功。
参考轨迹可能同时穿过障碍，例如镜片1某候选的参考与卫星本体相交；参考只作初值，
不执行。本轮这些候选首先在终点 IK 处失败。

### 4. B 臂两次接近存储镜片的 STOMP 超时

**镜片4/S4：** 起点与指定目标关节状态均有效。原运行和多次重放均出现约 12 秒
超时，`move_group` 明确记录 `TIMED_OUT`；任务层收到 99999，单看任务错误码无法识别。
关节直连在 **24/328** 点复现 `solar_panel_B ↔ arm_B_ur_forearm_link`。
该 IK 分支最大单关节变化约 4.915 rad，默认关节初值穿过太阳能板，STOMP 在当前
扰动/时间预算下未脱离这个路径。改用原运行后来成功的 IK 分支，同一记录起点下
STOMP 约 **0.39 秒**成功。

**镜片2/S2：** 起点、终点有效，原运行约 12 秒超时。直连在 **4/214** 点复现
`space_sim_carried_lens_4 ↔ arm_B_gripper_dock`，即夹爪绕过已安装镜片4时碰撞。
原分支重放有成功情况（约 3.88、5.69、6.83 秒），说明该超时依赖优化扰动与预算，
不能解释成目标不可达。原运行后来成功的另一 IK 分支重放约 **0.14 秒**成功。

两处回退直连都被碰撞检查拒绝，实际执行的是后续 IK 分支的 STOMP 轨迹，
没有执行穿过障碍的直连。

### 5. 中心 S3 转运：为何 B 会等待 A

原运行两次在预测时间约 **3.338 s / 2.934 s** 检出
`space_sim_carried_lens_5 ↔ space_sim_carried_lens_3`。
场景快照确认：镜片3附着于 B，镜片6附着于 A，镜片5仍是存储区世界对象。
所以这两处不是两臂互撞，不能仅凭对侧存在在途轨迹就归因于对侧机械臂。

用相同场景、起点和目标重放 STOMP，然后复用当前 **TOTG(.1,.1)+Ruckig**
处理并加密检查：

- 场景41的第六次优化重放：原始轨迹第29段中点与卫星本体相撞，尽管规划返回成功；
  平滑后仍有此碰撞。说明仅检查规划离散点还不足以保证段间安全。
- 场景45的第七次重放：原始路径加密检查通过，**平滑后的第31段中点复现了与
  存储区镜片5的相同接触对**。说明时间参数化/平滑后的路径可以改变原有避障几何。

保存了两条原始/平滑轨迹和触发碰撞的完整12关节状态，可直接检查，无需再次随机规划。
这重现了相同场景与相同接触对；STOMP 随机生成的轨迹不与首次运行逐点相同。

代码中的两个问题：

1. `motion_bridge.cpp` 只在 `optimizer_only` 或可达下降前缀时调用完整的
   `checkCollisionPath`；一般转运、预装配和 home 的平滑结果没有统一做该复检。
2. `validateOverlap` 检查完整场景，发现任意碰撞均返回“双臂轨迹…”；后续逻辑据此
   等待 peer，即便接触来自当前臂与静态对象。于是静态路径问题表现为“B 原地等 A”。

这次两条轨迹被重叠检查拦截。上述复检缺口和等待分类逻辑仍需修复；本次未改变
运动策略，只补充可复现的 DEBUG 轨迹/碰撞状态日志。
